# AI 引擎配置与插件内部服务

状态：已确认并实现。用户已确认完整范围并授权开发，内部调用说明见 [AI 服务使用指南](ai-engine-usage.md)。

## 已确认需求

- 设置中新增 AI 引擎模块，管理多份有名称的 AI 引擎配置。每份配置关联一个厂商连接与一个模型，同一厂商可创建多份配置。
- 连接信息包含 base URL 与 API Key 的配置入口。
- 首批厂商为 DeepSeek（V4）、百炼和有道智云大模型网关。用户原文「案例百炼」目前按阿里云百炼理解；有道已明确采用 API Key 鉴权的大模型网关。
- 统一服务仅供本插件内部功能调用。
- 后续用途包括翻译、生成卡片、解释答案和处理图片。本次建设设置与公共服务，生成卡片另行提出需求并开发。
- 设置全局默认配置。功能可单独指定配置，未指定时使用全局默认配置；调用失败时明确报错，不自动切换厂商。
- 模型支持从列表选择和手动填写模型 ID。厂商支持查询时加载模型列表。
- 首版支持文字与图片输入，返回文本，覆盖图片理解、文字识别及基于图片生成文本；不包含图片生成与编辑。
- 首版等待完整结果后返回，不实现流式逐字显示。
- 暂不设计或实现结构化输出、结果格式校验及卡片字段映射；生成卡片的需求单独开发。
- 功能显式指定的配置不存在或失效时明确报错，提示重新选择，不回退到默认配置。删除默认配置后清空默认项；缺少可用默认配置时，未指定配置的调用明确失败。
- 配置修改仅影响之后发起的请求，进行中的请求继续使用启动时确定的配置。
- 调用方提供图片数据及其类型，公共服务负责发送。已知模型不支持图片时提前提示；能力未知的手填模型允许尝试，并明确返回厂商错误。
- 设置提供独立的「测试连接」按钮，发送简短文本请求，并提示可能产生费用。保存仅校验必填项和格式，连接测试失败不阻止保存；文本测试成功不等于图片能力已验证。
- 请求默认等待上限为 120 秒，调用方可以调整并取消等待。取消或超时后不再交付迟到结果；取消等待不保证厂商停止生成。
- 首版不自动重试请求，避免重复计费。

## 现有代码约束

- 现有 AI 调用只有发音模块的 OpenAI TTS，没有通用文本或图片服务。
- API Key 值沿用 Obsidian SecretStorage 保存，插件数据只存密钥引用。
- 插件入口装配共享服务，Obsidian 适配层注入请求与持久化能力，React 消费快照与语义动作。
- 网络请求使用 Obsidian API；已有请求封装不等同于原生流式传输或底层 HTTP 中止能力。
- 设置写入必须沿用串行保存和持久化成功后发布的约束，避免旧设置快照覆盖新配置。
- 相关架构依据：[设置视图模型](../adr/0003-settings-view-model.md)、[发音运行时拥有配置](../adr/0009-pronunciation-runtime-owns-configuration.md)。

## 厂商文档调查

以下为 2026-09-10 调查结果，不能仅凭兼容协议推断每个模型都支持相同能力。

- [DeepSeek 官方](https://api-docs.deepseek.com/)提供 OpenAI 兼容调用，使用 API Key。V4 包含 `deepseek-v4-flash`、`deepseek-v4-pro`，图片输入有独立实验模型。
- [阿里云百炼](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)提供 OpenAI 兼容调用，端点和凭据受地域、工作空间及服务类型影响。[模型目录](https://help.aliyun.com/zh/model-studio/list-models)有独立接口，不能统一假设为兼容 base URL 后追加 `/models`。
- [有道智云大模型网关](https://ai.youdao.com/DOCSIRMA/html/thinkflow/api/guide/index.html)使用 API Key，可通过兼容接口调用模型。[子曰大模型翻译](https://ai.youdao.com/DOCSIRMA/html/trans/api/dmxfy/index.html)属于另一项服务，不能混为同一适配。
- 同一个模型可以由不同厂商托管；厂商连接与模型 ID 是不同概念。

## 已确认的交付边界

- 保留已有发音服务和 TTS 配置，本次不迁移到 AI 引擎模块。
- 公共接口接收调用方提供的消息及图片数据，不直接读取笔记、不修改 Markdown；内容选择与结果应用由未来功能负责。
- 多个功能可以分别发起请求，取消与超时按请求独立处理；首版不增加批量任务队列或聊天历史管理。

## 公共服务职责

以下为根据已确认需求整理的接口职责，具体 TypeScript 命名在实现时遵循现有模块风格。

- 配置管理：读取配置快照，新增、修改、删除配置，设置或清空默认配置。
- 模型发现：按厂商连接加载可用模型；查询失败可继续手动填写模型 ID。
- 连接测试：测试指定配置并返回结果。
- 内容生成：接收消息、可选图片、可选配置标识和请求级等待/取消选项，返回完整文本或明确的失败结果。
- 调用不携带配置标识时才解析全局默认配置。配置使用稳定标识，重命名不影响功能引用。
- 服务负责配置解析、凭据读取、厂商协议适配和请求生命周期；不负责业务提示词、结果格式校验或卡片内容写入。

## 验收范围

- 多配置的新增、修改、删除、默认选择及重启后恢复；密钥值不进入插件数据。
- 模型列表与手动输入，以及模型查询失败时仍可配置。
- 文本、图片请求，厂商错误、失效配置、不支持图片、超时与取消的处理。
- 在途请求与配置修改隔离，多个请求的结果和取消互不影响。
- 设置并发保存不覆盖已提交的新配置。
- 提供插件内部调用示例，并执行相关测试、构建与 lint；真实厂商连通性和 Obsidian 手动验证按实际可用环境报告。
